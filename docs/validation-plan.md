## По каким правилам идёт проверка?

1. **План фиксируется до результатов.** Версия плана для первого прогона — содержимое этого файла
   на момент первого запуска; дата фиксации — дата коммита в истории репозитория.
2. **Любая правка — только записью в [журнал](#журнал-изменений):** дата, что было, что стало,
   причина и видели ли мы результаты по этой метрике. После первого прогона отчёт показывает вердикт
   и по исходной, и по исправленной версии.
3. **Настройка отделена от оценки.** Параметры, помеченные «подбирается», выбираются только на
   настроечном наборе по правилу из этого плана. Метрики считаются на наборах, где ничего не
   настраивается.
4. **Истина отделена от признаков.** {{Эталонная разметка или скрытая истина лежит отдельно; код
   решения её не читает, и это проверяет тест `{{тест}}`.}}
5. **Отрицательный результат публикуется как есть,** с разбором причины. Метрика без данных помечена
   «ожидает данных», а не пропускается.
6. **Одна команда собирает отчёт:** `{{команда}}` прогоняет всё по фиксированным сидам и пишет
   `{{путь к отчёту}}`. Отчёт руками не правится; повторный прогон даёт тот же файл байт в байт.

## Какие метрики и пороги?

Порог — значение, при котором метрика получает вердикт «хорошо». Если не сказано иное, метрика
считается на D1 и повторяется на D2.

как агрегируется.}} Базовые линии — B0, B1. **Порог:** {{не ниже X и не ниже лучшей базовой линии плюс Y}}.
