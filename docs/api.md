## Как выглядит ошибка?

Тело ошибки одно на весь API:

```json
{
  "code": "{{snake_case_code}}",
  "message": "{{English message for logs and developers}}"
}
```

`code` — машинный код: фронтенд показывает текст из своих словарей по ключу `errors:api.<code>`.
`message` — по-английски, для логов и разработчиков; в интерфейс не попадает.

| Статус | Когда |
|---|---|
| 400 | {{Запрос корректен по схеме, но неверен по смыслу: истёкшая ссылка, неверный код}} |
| 401 | Нет входа |
| 403 | Чужая роль |
| 404 | Записи нет или она чужая |
| 409 | Действие недоступно в текущем состоянии: {{примеры}} |
| 422 | Запрос не прошёл проверку схемы или правил |
| 503 | {{Внешний сервис не отвечает, запасного пути нет}} |

| `code` | Статус | Когда |
|---|---|---|
| `{{code}}` | {{409}} | {{Условие}} |

## Как меняется контракт?

Несовместимое изменение выкатывается в три шага: фронтенд понимает обе формы → бэкенд переходит на
новую → старая форма удаляется. Типы фронтенда пересобираются из OpenAPI в том же изменении, где
меняется API.
