# Автоматическое заполнение карточки

Один запуск определяет категорию, извлекает характеристики и показывает цитаты. Если настроен Jev,
спорные кандидаты отправляются ему автоматически. При отсутствии ключа работают правила;
неразрешённые значения остаются на проверку. Текст продавца передаётся модели как данные.

## Что работает

| Было | Теперь | Результат |
|---|---|---|
| Шаблонный экран проверки API | Поле ввода и потоковый результат | Вставка текста и один запуск без предварительного выбора категории |
| `500 г` могло стать `500 кг` | Совместимые единицы переводятся через базовую размерность | `0.5 кг` с исходной цитатой `500 г` |
| Одинаковое число в разных единицах совпадало | Ключ содержит приведённое число и единицу | `1 кг = 1000 г`, но `1 кг ≠ 1 г` |
| `12/256GB` давало кандидатов в обе памяти | Позиции RAM/ROM разделены, цитата содержит всю запись | 12 ГБ RAM и 256 ГБ ROM без ложного конфликта |
| Аксессуары и отрицания могли заполнить поле | Фильтры контекста исключают проверенные случаи; конфликт уходит в review | Неподтверждённое значение не попадает в список заполненных |
| Отсутствующий профиль исчезал из оценки | Все обязательные поля учитываются; есть unsupported и candidate recall | Знаменатель метрик больше не зависит от обученных профилей |
| DecisionModel существовал отдельно | Автоматическая маршрутизация и повторная проверка контекста | Не требуется кнопка «вызвать AI» |
| Не было результата для выгрузки | JSON со значениями, цитатами и отдельным unresolved | Можно скачать результат одного запуска |

## Путь данных

`POST /api/v1/extract` выдаёт JSON Lines: `category`, `rules`, `complete`.
Первые два события содержат реально вычисленный результат, без искусственных задержек.
Нормализованный `source_text` и позиции `start/end` используют Unicode code points, а не байты.
Фронтенд учитывает это при выделении цитаты, включая символы за пределами BMP.

Категория определяется по ключевым словам первой строки. При неоднозначности пользователь выбирает
из предложенного списка. Это ограниченная маршрутизация по настроенной таксономии, не обученный
универсальный классификатор. Каталог по умолчанию явно помечен как демонстрационный и поддерживает
смартфоны и ноутбуки; произвольный текст обрабатывает настоящий код извлечения.

Jev выбирает только переданные кандидаты или `none`. Проверяются набор вариантов, диапазон и сумма
вероятностей, согласованность выбора с вероятностями и точность цитаты. Не более двух обращений
на карточку в пределах `DECISION_MODEL_TIMEOUT_S` (по умолчанию 10 секунд). Если первый ответ
не разрешил спор, повтор передаёт контексты кандидатов и инструкцию сохранить `none` при конфликте.
Сбой возвращает результат правил с предупреждением. Отмена запроса отменяет ожидаемый вызов модели.

Проверенные ответы кэшируются в памяти процесса, до 128 записей. Ключ включает карточку, категорию,
версию каталога, варианты, текущие принятые и спорные поля, модель, порог и политику.
Поэтому кэш прежнего решения не может вернуть поле поверх свежего исправления. Это кэш повторных последовательных запросов,
не долговременная идемпотентность; одновременные одинаковые запросы пока не объединяются.

## Уверенность и ограничения

`score_kind=heuristic` означает балл правил, `model_probability` — сырую вероятность модели.
`confidence=null`: калибратор ещё не обучен. Эти величины не выдаются за измеренную вероятность
корректности. Демо-порог правил 0.35 и порог Jev 0.9 не подтверждают целевой precision 95%.

Экспорт разделяет `fields` со статусом `accepted` и `unresolved`; содержит версию каталога,
признак демонстрационных данных, длительность, число обращений и доступную статистику модели.
Неизвестная стоимость остаётся `null`, не превращается в нулевую.

Контекстные фильтры — ограниченные эвристики. Протестированные отрицания, совместимость, аксессуары,
диапазоны и конфликт цветов не доказывают отсутствие ошибок на всех формулировках. Отсутствие
кандидата означает «нет подтверждения», а не доказанное отсутствие характеристики в карточке.

Исправления, подтверждённые алиасы, версии и отмена сохраняются в SQLite. Каталог тоже читается
из SQLite; миграции и seed выполняются отдельными командами до старта API.
CatBoost, калибровка, групповая оценка без пересечения семейств и полная абляция остаются следующими
этапами. Платных вызовов при разработке не было. Качество новой версии на каталоге не измерено.

## Исправления и обучение словаря

Для спорного поля предлагаются допустимые нормализованные кандидаты и их цитаты. Одно действие
принимает значение только для этой карточки или вместе с показанным алиасом. Алиас ограничен
категорией, брендом и атрибутом; неизвестное каталогу значение не становится каноническим. Если
кандидата нет, доступна ручная форма с точной цитатой. Числа должны подтверждаться числовым
кандидатом с совместимыми единицами; числовые и брендовые алиасы запрещены.

После сохранения экран автоматически повторяет извлечение. Прямое исправление помечается
`source=human`, `score_kind=human_confirmation`, без выдуманной вероятности. Следующая подходящая
карточка использует `confirmed_alias`. Исправление привязано к хешу нормализованного текста;
изменившаяся карточка получает только подходящий алиас, а не старое точечное исправление.

UUID запроса обеспечивает идемпотентность; другая нагрузка с тем же UUID и конкурирующая активная
правка возвращают 409. Отмена хранит историю и повышает версию, прекращая применение этой правки
и её алиаса в следующих извлечениях. Другая активная правка с таким же подтверждённым алиасом
может продолжать его поддерживать. Baseline и аудит не читают пользовательские исправления.

## Автоматический аудит

`audit-catalog` использует только train для словаря, сравнивает все четыре сплита и не меняет
исходный benchmark. Ищет точные совпадения нормализованного текста и совпадения ключа
«категория + gold-бренд + gold-модель без объёма памяти». Второй ключ — эвристика семейства,
не проверенная идентичность товара. Gold используется только для диагностического группирования,
не добавляется во вход извлечения.

Расхождения группируются по атрибуту и причине: unsupported, wrong_selection, review,
missing_candidate. Для каждой группы берутся пять примеров с минимальным SHA-256 от seed, SKU
и группы. Seed по умолчанию 42; правила и seed записываются в отчёт. Причины являются гипотезами,
эталон не проверен независимо человеком. Отчёт содержит размеры, текст, gold, ответ, цитату,
версию кода и SHA-256 входных файлов. Команда отказывается перезаписывать существующий отчёт.

Новая оценка `baseline` пишет `baseline_v2*`; прежние `baseline*` сохранены. Старое поле `ceiling`
оставлено для совместимости JSON, но это диагностическое совпадение с текстом, не верхняя граница
достижимого качества. Candidate recall считается отдельно от финального recall.
