# Извлечение — каскад «справочники → кандидаты с цитатой → decision-модель выбирает», значение вне списка невозможно

Кейс требует нормализацию, уверенность, отсутствие выдуманных значений и экономию на масштабе
(раздел 3; с. 12, 15). Каскад:

1. **Справочники:** канонические значения и алиасы каждого атрибута из эталона train.
2. **Кандидаты:** правила и словари находят значения в тексте карточки (словарный поиск, «число +
   единица», «ключ: значение»); у каждого кандидата есть цитата — фрагмент текста.
3. **Выбор:** decision-модель (TypeSafe Jev по контракту `/v1/systemone`, [ADR 0003](0003-llm-behind-port.md))
   по каждому обязательному атрибуту получает вопрос-выбор: варианты — кандидаты и «в тексте не указано»;
   возвращает выбор и вероятности. Все атрибуты карточки — одним запросом.
4. **Порог:** выше — в карточку, ниже — в очередь проверки; правка человека пополняет справочник алиасов.

Ранжировщик CatBoost на признаках кандидата — дешёвый обученный базлайн для абляции
«правила → CatBoost → decision-модель».

## Рассмотренные варианты

- **LLM с JSON Schema (Claude) как основной выбор:** отклонено — уверенность, написанная текстом, не
  калибрована, а значение вне списка остаётся возможным; Claude — запасной путь для новых категорий,
  если decision-модель недоступна.
- **Fine-tune BERT/NER:** отклонено на хакатон — не окупается за сутки; следующий шаг в презентации.
- **LLM или decision-модель на каждую карточку без кандидатов:** отклонено — нет цитаты, дороже.

## Следствия

- Значение без цитаты не принимается ни на одной ступени; decision-модель не может вернуть вариант
  вне списка — это проверяет адаптер.
- Потолок recall — доля пар, где значение эталона есть в тексте (~58% по EDA); recall публикуется и
  абсолютный, и относительно потолка.
- Порог выбирается на валидации; калибровка вероятностей вендора проверяется reliability-диаграммой.
- У Laya точность падает выше ~20 вариантов, поэтому варианты сужаются до топа кандидатов.
