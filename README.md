# mvideo

Автоматическое заполнение характеристик товаров по тексту продавца. Каталогизатор вставляет
карточку один раз и получает нормализованные значения с цитатами и JSON для выгрузки.

[Запуск](#запуск) · [Документация](docs/README.md) · [Ограничения](#ограничения)

## Как это работает

1. По первой строке определяется категория. При неоднозначности стенд предлагает выбор.
2. Словарь и правила извлекают кандидатов, приводят единицы и проверяют контекст цитат.
3. Настроенный Jev проверяет спорные значения в фоне, максимум за два обращения.
4. Экран показывает заполненные поля и исключения. Цитата открывает исходный текст;
   экспорт разделяет принятые и неразрешённые значения.
5. Исправление исключения сохраняется в SQLite и автоматически запускает повтор. Подтверждённый
   алиас применяется к следующим карточкам той же категории, марки и характеристики; доступна отмена.

Без ключа работают правила. Поля без подтверждения не заполняются догадками.
Точность контекстных эвристик на реальном каталоге ещё предстоит измерить.

## Попробовать

Вставьте в открытый стенд:

```text
Смартфон Samsung Galaxy S26 12/256GB Black
Вес: 500 г
```

Нажмите «Заполнить карточку». В демонстрационном словаре результат содержит Samsung, Galaxy S26,
чёрный цвет, 12 ГБ RAM, 256 ГБ ROM и 0.5 кг. У каждого значения есть цитата; отсутствующие
диагональ и ёмкость аккумулятора остаются незаполненными. «Скачать JSON» сохраняет результат.
Это синтетический пример для проверки сценария, не измерение качества на датасете.

## Запуск

Нужны Docker и Compose v2. Из корня:

```bash
docker buildx bake
docker compose up
```

Интерфейс: http://localhost:8080. API: http://localhost:8000/docs.
Compose применяет миграции и идемпотентно загружает демонстрационный каталог в SQLite.
Именованный том сохраняет исправления после перезапуска. Первичная сборка требует сети;
после сборки режим правил не требует платных ключей.
Параметры Jev, запуск без Docker и команды проверок: [инструкция запуска](docs/running.md).

## Проверки и качество

- `cd backend && uv run ruff check . && uv run mypy . && uv run pytest tests/unit`
- `cd frontend && npm run verify`
- На запущенном backend без модели: `cd backend && DBMATE_BIN=dbmate TEST_API_URL=http://localhost:8000 uv run pytest tests/integration`
- На запущенном стенде: `cd frontend && E2E_BASE_URL=http://localhost:8080 npm run e2e`

Оценка учитывает все обязательные поля, включая неподдерживаемые. Candidate recall и доля
проверки считаются отдельно. Новые отчёты имеют префикс `baseline_v2`; исторические результаты
не перезаписываются. `audit-catalog` автоматически ищет пересечения сплитов и собирает
воспроизводимые примеры расхождений. [Алгоритм и метод аудита](docs/automatic-catalog.md).

Качество новой версии на датасете не измерено. Баллы правил и вероятности Jev ещё не калиброваны;
поле калиброванной уверенности в API равно `null`. Значение precision 95% не заявляется как результат.

## Устройство

React, Vite и TypeScript на фронтенде; FastAPI и Clean Architecture на backend.
`DecisionModel` отделяет сценарий от TypeSafe System One. Поток JSON Lines передаёт реальные
этапы вычисления; nginx не буферизует API-ответы.

## Ограничения

- **Демонстрационный словарь:** смартфоны и ноутбуки; автоматическая категория определяется ключевыми словами.
- **Алиасы ограничены областью:** только известные категориальные значения, категория + бренд + атрибут. Числовые исправления требуют подтверждающего кандидата и не создают алиас.
- **Обучение и измерения не завершены:** CatBoost, калибратор, независимая проверка эталона и полная абляция остаются открытыми.
